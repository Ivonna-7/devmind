JavaScript 闭包的原理与常见陷阱

张三 · 2026-05-10 · 更新于 2 天前

什么是闭包

闭包（Closure）是指一个函数可以访问其外部函数作用域中的变量，即使外部函数已经执行完毕。 这是 JavaScript 中最重要的概念之一，也是函数式编程的基石。

简单来说：内部函数 + 它记住的外部变量 = 闭包。

function counter() {
  let count = 0;
  // 返回的这个函数记住了 count
  return function () {
    return ++count;
  };
}

const inc = counter();
inc(); // 1
inc(); // 2 - count 没有消失

常见陷阱

99% 的面试追问都从这里开始：「for 循环里用 var 定义循环变量，为什么 setTimeout 打印的全是最终值？」
  1. var 的函数作用域：所有异步回调共享同一个 i
  2. let 的块级作用域：每次循环创建新绑定，各自独立闭包
  3. IIFE 变通：立即执行函数捕获当前值，ES5 时代的经典解法
  4. 内存泄漏风险：闭包持有的 DOM 引用不会被 GC 回收

实战场景

闭包不只是面试题，它在以下场景大量使用：

  • 模块私有状态：React Hooks、Vuex 的 state 本质都是闭包
  • 柯里化与偏函数应用：curry、partial 必然用闭包
  • 防抖节流：debounce/throttle 的 timer 靠闭包保留
  • 事件处理器私有数据：给每个按钮绑定独立状态
[ 闭包作用域链示意图 ]

我会分三层回答：

1. 定义：闭包 = 函数 + 它引用的外部作用域。

2. 本质：JS 引擎在函数创建时保留对词法环境的引用，即使外层执行完，被引用的变量也不会被回收。

3. 实战：Hooks、柯里化、防抖、模块私有状态都是闭包的应用，我在项目中用它实现过 XX。
